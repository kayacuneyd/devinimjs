# CodeIgniter 4 + SQLite CMS kit

A complete, working CMS starter: CodeIgniter 4 backend (REST API, session auth, migrations,
seeders, plugin system, media library) + SQLite database + a DevinimJS-driven admin SPA and a
server-rendered public theme — the full backend half of the DevinimJS roadmap
(`devinimjs-yol-haritasi.md`, **Bölüm 2.1–2.10**), expanded into drop-in files.

Unlike the HTML kits, this kit is a **PHP overlay**: it is not generated by
`scripts/create-project.mjs`. You create a stock `codeigniter4/appstarter` project and copy
this kit's `app/` (plus `env.example`, `public/assets/admin/`) over it — nothing is rebuilt,
no build step anywhere (CI4 runs from source, DevinimJS ships as plain ES modules).

## Based on

- `devinimjs-yol-haritasi.md` Bölüm 2 (Backend API & Entegrasyon) — every code sketch there is
  implemented here, expanded to production quality.
- ADR-001 … ADR-006 mapping at the bottom of this file.
- CI4: targets `codeigniter4/appstarter` 4.4+ (4.5+ recommended — model `$casts` with `json`
  need ≥ 4.4). PHP 8.2+ with `sqlite3` and `gd` extensions.

## What's in the box

```
app/
  Config/        Routes, Database (SQLite), Filters (+ apiAuth alias), Boot/production (WAL)
  Controllers/   Auth, Admin (SPA shell), Content (public site), Api/* (REST resources)
  Models/        User, ContentType, Field (json-cast config), Content (json-cast data), Media
  Database/      One migration (users, content_types, fields, contents, media) + 2 seeders
  Filters/       ApiAuthFilter — 401 JSON for guests
  Libraries/     Hook + PluginLoader (roadmap 2.5), Fields/* (12 field types + factory)
  Commands/      db:backup (timestamped SQLite copies)
  Plugins/Blog/  Working example plugin (route + hook + manifest event)
  Views/         auth/login, admin/shell, themes/default/{layouts,partials,templates}
public/assets/admin/app.js   Admin SPA (dashboard, posts, editor, media, settings)
env.example                  SQLite-ready .env template
writable/README.md           chmod + Apache notes
```

## Install

```bash
# 1) Stock CI4 app (Composer runs locally OR on the host — not part of this repo)
composer create-project codeigniter4/appstarter cms
cd cms

# 2) Overlay the kit (paths shown from this repo's kits/ci4-cms directory)
cp -R app/. /path/to/cms/app/
cp env.example /path/to/cms/.env          # then edit app.baseURL
mkdir -p /path/to/cms/public/assets/admin
cp public/assets/admin/app.js /path/to/cms/public/assets/admin/

# 3) DevinimJS runtime → public/assets/devinim/ (copy the npm package src/, which
#    matches the module contract: core/core.js, core/authoring.js, core/app.js,
#    components/dv-media-upload.js, …)
mkdir -p /path/to/cms/public/assets/devinim
cp -R /path/to/devinimjs/src/. /path/to/cms/public/assets/devinim/
#    (or: npm pack devinimjs / copy from node_modules — same files, still no build)
#    Optional styling: copy CKCSS to public/assets/ckcss/ and uncomment the
#    <link> tags in app/Views/auth/login.php and app/Views/admin/shell.php.

# 4) Database: create schema + seed admin user and content types
php spark migrate --all
php spark db:seed UserSeeder
php spark db:seed ContentTypeSeeder

# 5) Writable dirs + media symlink (see writable/README.md for alternatives)
mkdir -p writable/uploads/thumbs writable/backups
chmod 775 writable writable/uploads writable/uploads/thumbs writable/backups
chmod 664 writable/database.sqlite
ln -s ../writable/uploads public/uploads

# 6) Run
php spark serve        # → http://localhost:8080
```

Then open **/admin** and log in:

> **Default credentials: `admin@example.com` / `devinim`**
> Seeded by `UserSeeder` on purpose and documented here so nobody forgets they exist.
> **Change the password (or the seed) before going live.** (`/api/users` update endpoint,
> or delete the user and seed your own.)

## How it fits together

- **Routing split (2.8 / ADR-002).** Public pages are CI4 routes (`/`, `/blog/{slug}`,
  `/sayfa/{slug}`, `/arsiv/{type}`) rendered server-side from `app/Views/themes/default/`.
  The admin panel is one CI4 route (`/admin`) serving `admin/shell.php`; inside it the
  DevinimJS hash router owns `/admin/#/posts`, `/media`, `/settings`, …
- **Auth (2.2 / ADR-004).** Plain CI4 sessions — no Shield. `GET /login` renders a standalone
  page that POSTs JSON to `/auth/login` (password_verify → session `user_id`/`user_email`).
  `ApiAuthFilter` guards the whole `/api` group with a JSON 401 (`{error, login_url}`), which
  the SPA turns into a redirect via createApi's `onUnauthorized`.
- **CSRF (2.10).** CI4's `csrf` filter is *off* for the API; instead the shell renders
  `csrf_hash()` into `<meta name="csrf-token">`, createApi sends it back as `X-CSRF-TOKEN`,
  and `BaseApiController::verifyCsrfHeader()` compares on every write (all three guards are
  one call: `guardWrite()`). Enable the stock `csrf` filter in `app/Config/Filters.php` if
  you add classic HTML forms.
- **API envelopes.** Lists: `{data: [...], meta: {page, limit, total}}`. Single rows:
  `{data: {...}}`. Errors: `{error: ...}`, validation: `{error, errors: {field: message}}` —
  `BaseApiController` pins these shapes regardless of CI4 version.
- **Content model (2.3 / ADR-005).** Fixed columns on `contents` + a JSON `data` column for
  the dynamic fields defined per content type in `fields` (`config` is JSON too). Query into
  `data` with SQLite JSON1: `json_extract(data, '$.summary')`.
- **Plugins (2.5 / ADR-006).** `app/Plugins/<Name>/plugin.json` + optional `Config/Routes.php`
  (registered from `app/Config/Routes.php` via `PluginLoader::boot($routes)`), `Config/Hooks.php`
  and manifest `events` (registered on every controller boot). `Blog` ships ACTIVE as a living
  example (`GET /api/blog/stats` + a `content.before_save` listener); set `"active": false` to
  disable. Plugin classes autoload as `App\Plugins\<Name>\…` via the appstarter PSR-4 map.
- **Field library (2.3).** `App\Libraries\Fields\FieldFactory::make($type, $name, $config)` →
  `render($value)` (CKCSS-friendly `input`/`textarea`/`select` classes, `esc()` everywhere) and
  `validate()` (CI4 rule fragments). Types: text, textarea, rich_text, number, boolean, date,
  datetime, image, file, select, multi_select, relation.
- **SQLite in production (2.7).** `app/Config/Boot/production.php` sets `PRAGMA journal_mode=WAL`
  + `synchronous=NORMAL` (try/catch + log on failure; WAL persists once set). Backups:
  `php spark db:backup` → `writable/backups/database_<timestamp>.sqlite` — cron it daily.

## REST API

All under `/api`, behind `apiAuth` (session) + AJAX + CSRF-header guards.

| Endpoint | Method(s) | Notes |
|---|---|---|
| `/posts` `/pages` | GET/POST, GET/PUT/DELETE `/{id}` | list params: `page`, `limit`, `q`, `status` |
| `/posts/search?q=` | GET | declared before the resource so it beats `show` |
| `/posts/{id}/publish` | POST | sets `status=published`, stamps `published_at` once |
| `/posts/{id}/duplicate` | POST | copies as a new draft, unique `-kopya` slug |
| `/media` | GET, GET/DELETE `/{id}` | paginated; delete removes files + row |
| `/media/upload` | POST | multipart field `image`; 5 MB max; png/jpg/jpeg/gif/webp; GD 300×300 thumb |
| `/users` | full CRUD | model-callback password hashing; hashes never leave the server |
| `/content-types` | full CRUD | `show` embeds `fields`; create/update accept a `fields` array |
| `/blog/stats` | GET | from the example Blog plugin |


## Deploy to shared hosting

```bash
# Permissions (see writable/README.md for details + Apache .htaccess note)
chmod 775 writable/
chmod 664 writable/database.sqlite
chmod 775 writable/uploads/ writable/backups/

# One-command deploy (roadmap Bölüm 5):
rsync -avz --exclude='.git' --exclude='tests' ./ user@host:public_html/
```

Checklist: `.env` has `CI_ENVIRONMENT = production` and the real `app.baseURL`; the default
admin password is changed; `writable/` is outside the docroot (or denied via `.htaccess`);
`public/uploads` symlink exists (or the upload path was moved to `FCPATH`).

## Security map (roadmap 2.10)

| Threat | Where it's handled |
|---|---|
| SQL injection | Query Builder / Models only — no raw queries except the two WAL pragmas |
| XSS (output) | `esc()` on every view echo; DevinimJS `html` auto-escapes; `rich_text` bodies are raw-by-design trusted admin HTML (see `RichTextField`) |
| CSRF | `csrf_hash()` meta tag → `X-CSRF-TOKEN` header → `verifyCsrfHeader()` on writes; login POST included |
| File upload | `uploaded`/`max_size`/`ext_in` validation, random server-side names, files outside docroot |
| Auth bypass | `apiAuth` filter + in-controller `requireAuth()` (defense in depth); `AdminController` session guard |
| Session fixation | `session()->regenerate(true)` on login |

## Roadmap ADR mapping

| ADR | Decision | Where in this kit |
|---|---|---|
| ADR-001 | Light DOM (CKCSS classes apply directly) | admin SPA components render light DOM; shell/login carry plain CSS |
| ADR-002 | Hash router for admin, CI4 routing for public | `admin/shell.php` + `app.js` vs. `ContentController` |
| ADR-003 | SQLite default, MySQL optional | `app/Config/Database.php` (env-overridable) |
| ADR-004 | Custom session auth, not Shield | `AuthController`, `ApiAuthFilter`, `users` table |
| ADR-005 | JSON field + fields metadata, not EAV | `contents.data` (json cast) + `fields.config` |
| ADR-006 | Plugin sandbox = namespaces + hooks | `PluginLoader`, `Hook`, `app/Plugins/*` (`App\Plugins\…` autoloading) |

## Customizing

- **New content type:** insert into `content_types` + `fields` (or POST `/api/content-types`),
  add a `templates/<slug>.php` theme file, and — for admin CRUD — a 5-line
  `ApiContentController` subclass plus a resource route.
- **New field type:** extend `BaseField`, add one line to `FieldFactory::MAP`.
- **New plugin:** copy `app/Plugins/Blog/`, flip the slug, keep `"active": true`.
- **Theme:** duplicate `app/Views/themes/default/` and change the paths in `ContentController`.
